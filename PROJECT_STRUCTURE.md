## Key Directories Explained

### `/app` - Next.js App Router
- Uses the new App Router (Next.js 13+)
- Each folder is a route
- `layout.tsx` wraps all pages
- `page.tsx` files are route components

### `/components/dashboard` - Dashboard Components
- Custom components specific to the compliance dashboard
- Modular design for easy maintenance
- Each component handles one responsibility

### `/components/ui` - Shadcn UI Components
- Auto-generated by Shadcn CLI
- Fully customizable
- Based on Radix UI primitives

### `/lib` - Utilities
- Helper functions
- Shared utilities
- Type definitions

### `/hooks` - React Hooks
- Custom React hooks
- Reusable logic

## Tech Stack

- **Framework**: Next.js 16 (App Router, Turbopack)
- **Language**: TypeScript
- **Styling**: Tailwind CSS 4
- **UI Library**: Shadcn UI
- **Icons**: Lucide React
- **Authentication**: Clerk

## Development Workflow

```bash
# Install dependencies
npm install

# Set up environment (add Clerk keys)
cp .env.example .env.local
# Edit .env.local with your keys

# Run dev server
npm run dev

# Build for production
npm run build

# Start production server
npm start

# Lint code
npm run lint
```

## Adding New Components

### Shadcn UI Component
```bash
npx shadcn@latest add [component-name]
```

### Custom Dashboard Component
Create in `components/dashboard/your-component.tsx`

### Custom Hook
Create in `hooks/use-your-hook.ts`

## Code Organization Best Practices

1. **Components** - One component per file
2. **Naming** - PascalCase for components, kebab-case for files
3. **Imports** - Use path aliases (`@/components`, `@/lib`)
4. **Types** - Define interfaces inline or in separate `.d.ts` files
5. **Styles** - Use Tailwind utility classes

## Path Aliases

Configured in `tsconfig.json`:

```typescript
"@/*": ["./*"]
```

Usage:
```typescript
import { Button } from "@/components/ui/button"
import { cn } from "@/lib/utils"
```
